### Highlights (curated, high-level)

- **Wayland robustness** — daemon recovers from compositor restarts, owner
  changes, empty / unsupported / huge / duplicate clipboard events.
- **Robust MIME handling** — explicit fallback order for `text/html`,
  `text/plain;charset=utf-8`, `text/plain`, `image/png`, `image/jpeg`,
  `text/uri-list`; related representations are stored together.
- **Database correctness** — `get_history_page` / `search_page` /
  `count_*` APIs with SQL-backed pinned / starred / sensitive filters and
  correct `LIMIT`/`OFFSET` pagination.
- **Storage lifecycle** — deleting an image item or running TTL / max-items
  cleanup now also cleans the on-disk blob and thumbnail; a startup orphan
  scan plus `doctor --storage` and `repair --orphaned-files` keep the data
  dir tidy.
- **Security correctness** — sensitive detection runs on every content
  path (text, HTML plain, stripped HTML, URI lists, file paths, imports);
  constructors like `new_html()` and `new_files()` no longer silently
  mark content as non-sensitive.
- **Encryption at rest** — sensitive items are encrypted before insert when
  `encrypt_sensitive` is on; decryption happens only at the preview / copy
  boundary; no sensitive plaintext is allowed in logs, audit events,
  search indexes, UI previews, or exports.
- **Picker UX** — debounced search, matched-term highlight, filters
  (all / text / links / code / images / files / pinned / starred /
  sensitive), redacted sensitive previews, keyboard shortcuts
  (`Enter`, `Ctrl+Enter`, `Esc`, `Ctrl+D/P/S/L/R`, `PgUp`/`PgDn`,
  `Home`/`End`).
- **Applet UX** — daemon status, pause / resume, clear history,
  clear sensitive items, settings shortcut, storage usage summary,
  redacted last-copied summary.
- **CLI UX** — `status`, `history`, `search <query>`, `copy <id>`,
  `paste <id>`, `delete <id>`, `pin <id>`, `star <id>`,
  `clear [--sensitive]`, `pause`, `resume`, `doctor [--json|--storage|--security]`,
  `config path|validate`, `repair [--orphaned-files|--vacuum]`.
- **Audit events** — consistent event names
  (`ItemCaptured`, `ItemCopied`, `ItemQuickPasted`, `ItemPreviewed`,
  `SensitiveItemCopied`, `SensitiveItemPreviewed`, `ItemDeleted`,
  `ItemPinned`/`ItemUnpinned`, `ItemStarred`/`ItemUnstarred`,
  `HistoryCleared`, `SensitiveItemsCleared`, `CapturePaused`,
  `CaptureResumed`, `ConfigChanged`, `EncryptionKeyCreated`,
  `EncryptionError`, `DaemonStarted`, `DaemonStopped`, `DoctorRun`).
  No plaintext, no secrets, no full private paths.

### Open hardening work (planned for this cycle, not yet enforced)

These items are listed in `README.md` → "Planned" and are tracked under
`specs/features/022-hardening-pass/`:

- Sensitive content is **detected** on more paths, but the
  `encrypt_sensitive` flow is still gated on opt-in. Encryption is
  **not yet enforced** end-to-end; the CLI / applet / picker still
  expose plaintext previews unless the user explicitly reveals them.
- Orphan-blob repair (`repair --orphaned-files`) and `doctor --json`
  output are still being expanded.
- The UI policy path is in the middle of being unified (see Phase 4 of
  `specs/features/022-hardening-pass/`); until that lands, the picker,
  applet, and CLI each carry their own copy of "is this sensitive?".
