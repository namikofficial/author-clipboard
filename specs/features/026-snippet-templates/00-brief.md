# Brief: Snippet Token Replacement & Preview

> Turns the existing snippet CRUD into a real templating system:
> built-in variables (`${date}`, `${uuid}`, `${cursor}`, …) substitute at
> expand time, and the picker shows a live preview of the rendered output.
>
> Closes the second Phase 15 checkbox in `PROJECT_PLAN.md`:
> _"Snippets & templates with token replacement and preview"_.

---

## Problem

Today snippets are plain text: the user writes "Hello, my name is X" and
that's what gets pasted. Useful, but static. Common real-world needs:

- Greetings, signatures, or links that change with the day / time
- Boilerplate that wants today's date, current git branch, or a fresh UUID
- Repeated shell snippets that need the user's `$HOME` or `$USER`
- Code fences where the cursor should land in a specific spot after paste

These all need **variable substitution at expand time** plus a way to **see
the result before pasting** so the user isn't surprised.

## Goals

1. A small, predictable template syntax built on `${name}` with built-in
   variables only (no interactive prompts, no user-defined vars in v1).
2. A live preview in the snippet picker so the user sees rendered output
   next to the raw template.
3. The `${cursor}` marker is preserved as a cursor-position hint in the
   IPC response so a future "smart-paste" feature can land the caret.
4. A CLI command (`author-clipboard-ctl expand-snippet`) to render to
   stdout / clipboard without opening the picker.

## Non-Goals (documented in `09-decisions.md`)

- Interactive variable prompts when a snippet has unresolved variables
  (UX-heavy; preserved literally in v1).
- User-defined per-snippet variables (storage + UI scope).
- Shell command substitution (security-sensitive; rejected for v1).
- Snippet composition / includes (over-engineered for v1).
- Smart-paste that consumes `${cursor}` (separate feature; the offset is
  returned by the IPC but not yet consumed by the quick-paste subsystem).
