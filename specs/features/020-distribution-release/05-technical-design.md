## Design Decisions

### 1. Fix deb asset paths instead of moving metadata to workspace

`cargo-deb` resolves `[package.metadata.deb].assets` `source` paths relative to `CARGO_MANIFEST_DIR` of the package that owns the metadata. Putting the metadata on `crates/applet` (which is the natural home — that's the binary it builds) means the source paths must be `../../target/release/...` to reach the workspace `target/`.

Alternative considered: `[workspace.metadata.deb]`. Rejected because the applet crate is the only one we want to deb, and a single package's deb metadata is clearer.

### 2. Hypr-picker bundled in the .deb, not split

The hypr-picker is a first-party companion to the applet. It shares no IPC secret with the applet itself, but it does share data (the clipboard db via `XDG_DATA_HOME/author-clipboard`). Bundling it in the same .deb avoids a second package and a second AUR entry.

### 3. Arch validation runs in an Arch container, not on Ubuntu

`makepkg` is Arch-specific (it shells out to `pacman` and uses `/var/lib/pacman`). Running it on the Ubuntu CI runner would fail. The simplest fix is `archlinux:latest`. The job is small and only runs on PR, not on every push (kept in `ci.yml` because the spec says PR validation, not push).

### 4. GPG signing is conditional, not required

Most users verifying checksums just check the GitHub Release signature via the web UI. Requiring GPG signing in CI blocks releases if the maintainer key changes or is unavailable. The workflow:

1. Tries to import `GPG_PRIVATE_KEY` and `GPG_PASSPHRASE` from secrets.
2. If present, signs `SHA256SUMS` and uploads `SHA256SUMS.asc`.
3. If absent, uploads `SHA256SUMS` only and logs a warning.

This keeps the pipeline robust while making signing opt-in.

### 5. Nix flake uses `rustPlatform.buildRustPackage` for the binaries

`rustPlatform.buildRustPackage` is the idiomatic Nix helper. We pass the `Cargo.lock` and apply `RUSTFLAGS` to silence the upstream `libcosmic` warnings. We do **not** attempt to ship a NixOS module in this phase — the applet is a regular desktop app; a service can be added with `systemd.user.services` by the user.

### 6. AppImage is a thin wrapper

AppImages for wlroots apps are notoriously hard to make fully sandboxed. We ship a `build.sh` that produces a working AppImage for local testing, but document the limitation: the AppImage runs the binary directly without LD-level sandboxing. Flatpak is the recommended distribution form for sandboxed install.

### 7. Flatpak manifest uses `flatpak-github-actions` style

The manifest is hand-authored (not generated by a tool) to keep it auditable. The `finish-args` declare `--socket=wayland`, `--socket=fallback-x11` (we don't use X11 but COSMIC tests may), and `--filesystem=xdg-data/author-clipboard:rw`.

### 8. Reproducible builds

`SOURCE_DATE_EPOCH` is set to the commit timestamp in CI. The release workflow also pins the toolchain via `dtolnay/rust-toolchain@stable` and uses `--locked`. We document that bit-for-bit reproducibility across hosts is best-effort for now (the libcosmic git dep makes it harder) and that we use `cargo --locked` + `SOURCE_DATE_EPOCH` as the current contract.

### 9. Releases are explicit and do not write back to `main`

The release workflow runs only for tags matching `v[0-9]*`. Before any build,
it compares the tag with the workspace version, `PKGBUILD`, and `.SRCINFO`.
Version bumps are prepared and reviewed before tagging. CI does not create a
follow-up commit, avoiding recursive workflows and unreviewed branch mutation.

### 10. Arch dependencies are declarative

`gtk4-layer-shell` is a normal package dependency. The project `PKGBUILD` does
not clone another AUR repository, run nested `makepkg`, or install packages
during `build()`. CI installs dependencies before invoking `makepkg`, then
regenerates `.SRCINFO` and requires a byte-identical result.

### 11. Ubuntu CI builds gtk4-layer-shell from a pinned tag

Ubuntu 24.04 does not provide `libgtk4-layer-shell-dev`. Rust, Debian, and
release jobs therefore build and install upstream `gtk4-layer-shell` from the
explicit `v1.3.0` tag before compiling the workspace. Optional examples,
documentation, tests, introspection, and Vala bindings are disabled because CI
only needs the native library and pkg-config metadata.

### 12. Arch package builds run as an unprivileged user

The Arch container may install dependencies and generate the source archive as
root, but it changes workspace ownership and invokes `makepkg` through
`runuser -u builder`. Workflow steps use Bash explicitly so strict mode and
variable handling are consistent inside the container.

## Failure Modes

| Failure | Handling |
|---------|----------|
| `cargo deb` fails on a tagged build | Release job fails; no release is created. |
| PKGBUILD fails `makepkg` on a PR | PR is blocked; logs show the makepkg error. |
| `.SRCINFO` out of sync with PKGBUILD | CI job regenerates `.SRCINFO` and fails with `git diff` if there's a delta. |
| Tag and package versions differ | Release validation fails before artifact creation. |
| Debian package omits a required file | PR and release inspection steps fail before publication. |
| Ubuntu runner lacks gtk4-layer-shell packages | CI builds pinned upstream `v1.3.0` before compiling the workspace. |
| Arch `makepkg` is invoked as root | Workflow changes ownership and executes it through the `builder` account. |
| GPG key invalid / missing | Release still completes, logs a warning, omits `.asc`. |
| Flatpak manifest schema error | Documented; not validated in CI (flatpak-builder isn't preinstalled). |
| Nix flake fails on Darwin | Documented: flake defaults to Linux x86_64; aarch64 is best-effort. |

## Out of Scope (Documented but Not Implemented)

- AUR auto-publish (no AUR SSH key).
- Cross-architecture CI matrix.
- Snap store.
- RPM/COPR for Fedora.
